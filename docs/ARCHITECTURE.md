# 架构与数据口径

三个页面负责展示和交互，utils中的业务纯函数负责规则计算，store.js适配微信本地存储。页面读取数据后计算展示状态；打卡与取消更新对应习惯id的本地日期记录，再刷新统计与成就。

## 本地存储

| 键 | 逻辑结构 |
| --- | --- |
| habits | [{id, name, icon, color, createdAt}] |
| records | {habitId: {'YYYY-MM-DD': true}} |
| achievement_unlocks | {成就id: 'YYYY-MM-DD'} |

日期键按本地自然日计算。删除习惯会清理对应id的记录；新建同名习惯生成新id，不继承旧记录。

## 指标

- 当前连续：今天已打卡，从今天倒推；今天未打卡，从昨天倒推，遇到断点停止。
- 历史最长：从有效记录中寻找最长连续日期段。
- 累计次数：各习惯有效打卡记录相加。
- 活跃天数：跨习惯按日期去重，同一天多个习惯只记一天。
- 近7天、近30天完成率：滚动窗口内已完成天数除以相应窗口天数。
- 8周日历：每列一周、周一对齐，包含当周和未来格，不等于截至今天的56个完整自然日。

## 成就

14条规则以累计次数、历史最长连续、活跃天数和习惯数量为依据。evaluate计算当前是否达标，recordUnlocks仅补入新达成记录，applyUnlocks合并独立保存的历史解锁状态。首次发现达成的日期不会覆盖为后续刷新日期。

保存成功且存储未清除时，当前指标回落不撤销已保存成就。清除数据、写入失败或设备迁移仍可能造成丢失，当前没有云备份。
